# Loan Approval Prediction

End-to-end machine learning project: **synthetic CSV → cleaning → EDA → feature engineering → model training → evaluation → saved pipeline → FastAPI prediction service**.

## Overview

The project predicts whether a loan application is likely to be **approved (1)** or **rejected (0)**. A single scikit-learn `Pipeline` (feature engineering + imputation + outlier clipping + scaling + one-hot encoding + classifier) is trained, saved with `joblib`, and loaded by a FastAPI service, so training and serving use exactly the same preprocessing.

## Problem Statement

Lenders must decide quickly and consistently which applications to approve. Approving a risky loan causes credit losses; rejecting a good applicant loses business. This project builds a model that ranks applications by approval likelihood, and exposes it through an API.

## Dataset

* **Synthetic**, generated by `src/generate_dataset.py` (seed 42): **15,000 records, 17 features + target**.
* **Target:** `Loan_Status` (1 = approved, 0 = rejected); about **68% approved / 32% rejected**.
* **Numeric:** `ApplicantIncome`, `CoapplicantIncome` (annual), `LoanAmount`, `Loan_Amount_Term` (months), `Credit_History`, `ApplicantAge`, `EmploymentYears`, `ExistingLoans`, `DebtToIncomeRatio`, `Savings`.
* **Categorical:** `Gender`, `Married`, `Dependents`, `Education`, `Self_Employed`, `Property_Area`, `LoanPurpose`.
* **Missing values:** injected into 13 columns (about 0.5%-6% each, e.g. `Credit_History` ~6%, `Self_Employed` ~5%, `Savings` ~4%), plus a few extreme income outliers.
* **How labels are made:** approval probability comes from a latent score using credit history, income, estimated EMI-to-income ratio, debt-to-income ratio, existing loans, employment history, savings and small demographic/location effects. Labels are *sampled* from that probability, so the problem is noisy on purpose (a perfect model is impossible).

> **Important:** because the data is synthetic, the scores below measure how well the pipeline recovers the patterns built into the generator. They are **not** a claim about performance on real lending data.

**Engineered features** (inside the pipeline): `TotalIncome`, `MonthlyIncome`, `LogTotalIncome`, `LoanToIncomeRatio`, `EstimatedEMI`, `EMIToIncomeRatio`, `IncomePerDependent`, `SavingsToLoanRatio`, `EmploymentStability`.

**Leakage control:** the stratified 80/20 split (`random_state=42`) happens first; imputers, clipping bounds, scalers and encoders are fitted only on training data (inside cross-validation folds); `Loan_Status` is never a feature; the test set is used once, at the very end.

## Models

Compared with 5-fold stratified cross-validation on the **training set only**:

1. Logistic Regression (and a `class_weight="balanced"` variant)
2. Decision Tree
3. Random Forest (and a `class_weight="balanced"` variant)
4. Gradient Boosting
5. XGBoost - included automatically when the `xgboost` package is installed (it is listed in `requirements.txt`)

**Class imbalance:** the imbalance is mild (about 68/32), so SMOTE was not used; `class_weight="balanced"` variants were compared instead.

**Selection rule:** highest cross-validated ROC-AUC; models within 0.002 AUC are treated as tied and the higher F1 wins. Accuracy alone is never used. The chosen model is then tuned with `GridSearchCV` (5-fold CV, training data only).

## Evaluation

### Cross-validation comparison (training set, mean of 5 folds)

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression (balanced) | 0.8148 | 0.8943 | 0.8271 | 0.8593 | 0.8873 |
| Logistic Regression | 0.8339 | 0.8501 | 0.9195 | 0.8834 | 0.8872 |
| Gradient Boosting | 0.8275 | 0.8434 | 0.9185 | 0.8794 | 0.8821 |
| Random Forest | 0.8272 | 0.8421 | 0.9201 | 0.8794 | 0.8762 |
| Random Forest (balanced) | 0.8187 | 0.8682 | 0.8667 | 0.8674 | 0.8761 |
| Decision Tree | 0.8045 | 0.8240 | 0.9089 | 0.8642 | 0.8340 |

The two logistic regression variants tie on ROC-AUC. The tuning grid for Logistic Regression searched `C` and `class_weight`; the best CV combination was `C=0.1, class_weight="balanced"` (CV ROC-AUC 0.8873, F1 0.8592, accuracy 0.8146).

### Final model on the untouched test set (3,000 rows)

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression (tuned, balanced) | 0.8067 | 0.8802 | 0.8305 | 0.8546 | 0.8779 |

Confusion matrix (test): 715 true rejections, 232 wrongly approved, 348 wrongly rejected, 1,705 true approvals. Training-set scores are similar (accuracy 0.8168, ROC-AUC 0.8895), so there is no sign of overfitting.

### Target check

| Target | Result |
|---|---|
| Test accuracy >= 80% | 80.67% (met, with a small margin) |
| F1 >= 75% | 85.46% (met) |
| ROC-AUC >= 80% | 87.79% (met) |

The margin on accuracy is small. The generator's built-in noise limits the best possible accuracy to roughly 84%, so scores far above 81-83% would be a warning sign, not a success. Figures are saved in `reports/figures/` and metrics in `reports/test_metrics.json`.

### Explainability

Largest standardised logistic-regression coefficients: good `Credit_History` (+), `EMIToIncomeRatio` (-), `LogTotalIncome` (+), `ExistingLoans` (-), `DebtToIncomeRatio` (-), `SavingsToLoanRatio` (+). These describe what the model relies on; they do not prove causation.

## API Usage

Install dependencies (Python 3.11+):

```bash
pip install -r requirements.txt
```

Run the API from the project root:

```bash
uvicorn app.main:app --reload
```

* `http://127.0.0.1:8000` - API root (running message)
* `http://127.0.0.1:8000/docs` - interactive Swagger UI
* `http://127.0.0.1:8000/health` - health check

### Example `/predict` request

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "ApplicantIncome": 90000,
    "CoapplicantIncome": 20000,
    "LoanAmount": 220000,
    "Loan_Amount_Term": 360,
    "Credit_History": 1,
    "Gender": "Female",
    "Married": "Yes",
    "Dependents": "1",
    "Education": "Graduate",
    "Self_Employed": "No",
    "Property_Area": "Semiurban",
    "ApplicantAge": 38,
    "EmploymentYears": 10,
    "ExistingLoans": 1,
    "DebtToIncomeRatio": 0.12,
    "Savings": 150000,
    "LoanPurpose": "Home"
  }'
```

Response produced by the saved model for this input:

```json
{
  "prediction": 1,
  "loan_status": "Approved",
  "probability": 0.9389
}
```

The weaker example in the Swagger UI (income 50,000 + 10,000, loan 250,000 over 360 months, debt-to-income 0.25) gets `prediction: 0`, `probability: 0.2874`: the estimated instalment alone takes about 40% of income on top of existing debt.

Invalid input (negative income, `Credit_History: 2`, age outside 18-75, debt-to-income above 1, missing fields, ...) returns **HTTP 422** with details.

## Reproduce the Results

```bash
python -m src.generate_dataset   # creates data/loan_data.csv
python -m src.train_model        # compares, tunes, evaluates, saves the model (about 2 minutes)
python -m src.evaluate_model     # optional: re-evaluate the saved model on the test split
```

Run these from the project root (`python -m ...`) so the `src` package is importable.

## Testing

```bash
pytest
```

The tests cover the root and health endpoints, a valid prediction and its response structure, invalid values, missing fields and malformed bodies. Prediction tests need the trained model, so run `python -m src.train_model` first (they are skipped otherwise).

The model file is small and is committed, so no training is needed at deploy time. For lighter deploy builds you can use a trimmed requirements file without `jupyterlab`, `pytest` and `xgboost`. **This project has not been deployed.**

## Git: should the CSV and model be committed?

Both files are small here (the CSV is about 1.5 MB and the model a few KB), so committing them is fine and makes the repo runnable straight after cloning. GitHub warns above 50 MB and blocks files above 100 MB; if the dataset or model ever grows beyond that, use Git LFS (`git lfs track "*.csv" "*.pkl"`) or store them in object storage (S3, Hugging Face Hub, DVC). Pickled models depend on the scikit-learn version, so retrain if you upgrade it, and never load pickles from untrusted sources.
